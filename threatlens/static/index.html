eMudhra Incident: Protecting the Web's Trust Infrastructure

A real-world case study in Certificate Authority vulnerabilities, cryptographic key generation failures, and the importance of continuous PKI monitoring.

⚠️

The Root Cause

On 21 Oct 2026, eMudhra disclosed that eight intermediate Certificate Authorities in its global TLS hierarchy had flawed private keys due to a defective key-generation ceremony on 30 Apr 2025. The ceremony lacked sufficient entropy, rendering intermediate private keys predictable.

⚡

The Impersonation Risk

When an intermediate CA's private key is compromised or predictable, malicious actors can forge cryptographically valid TLS certificates for any domain on earth (including banks, universities, and government portals) without the domain owner's knowledge.

🛡️

Root Store Response

Google Chrome Root Program and Mozilla OneCRL responded decisively by adding the affected intermediate certificates to their distrust blocklists. eMudhra subsequently announced its phased exit from the global public TLS business.

🔍

How ThreatLens Detects It

ThreatLens inspects every intermediate CA in the TLS chain, not just the leaf. It checks SubjectPublicKeyInfo (SPKI) against known distrusted lists, matches intermediate issuers against active incident watchlists, checks Certificate Transparency (CT) proofs, and tests RSA moduli for shared prime factors via batch GCD.

Web Security Posture: How to Achieve an A+ Grade

Hardening guidelines for site administrators. The posture grade evaluates application-level resilience against clickjacking, script injection, downgrade attacks, and secret leakage.

Nginx Configuration

# Enable HSTS (1 year with subdomains and preload)
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

# Modern Content Security Policy
add_header Content-Security-Policy "default-src 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none';" always;

# Anti-Clickjacking & Sniffing
add_header X-Frame-Options "DENY" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

Apache Configuration (.htaccess / httpd.conf)

<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
  Header always set Content-Security-Policy "default-src 'self'; frame-ancestors 'none';"
  Header always set X-Frame-Options "DENY"
  Header always set X-Content-Type-Options "nosniff"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set Permissions-Policy "geolocation=(), camera=()"
</IfModule>

The Four Pillars of ThreatLens

1. Address & Brand Signals

Typosquatting detection, Levenshtein distance, homoglyph lookalikes (Cyrillic, Greek), Punycode / IDN spoofing, suspicious disposable TLDs, and brand-in-subdomain deceptive nesting.

2. Content & Phishing Behavior

Harvesting inputs for passwords, OTPs, MPIN, CVV, and PAN/Aadhaar; cross-domain form submissions; urgency and account suspension threats; recruitment fees; and obfuscated JavaScript.

3. Certificate & Cryptographic Health

Full X.509 chain audit, Fermat factorization for close primes, ROCA fingerprinting, trial division, batch GCD shared-prime checks, eMudhra distrust monitoring, and Certificate Transparency (SCTs).

4. Collaborative Intelligence

Privacy-preserving salted HMAC reporting, time-decayed Bayesian reputation, community confirm/dispute voting, anti-brigading brand safeguards, and exportable threat feeds.
